# Perbaikan uji terisolasi Coraza

## ✨ Fitur Baru
- Audit Hardening Situs di tab Audit: per situs nginx, Apache, dan OpenLiteSpeed (CyberPanel) memeriksa protokol TLS lama (yang tertulis di konfigurasi dan yang benar-benar diterima lewat handshake lokal), header keamanan ganda atau hilang, versi server yang terlihat di header, dan open_basedir situs PHP; tombol "Matikan TLS 1.0/1.1" mencadangkan vhost, menguji konfigurasi, me-reload dengan verifikasi, dan mengembalikan cadangan bila gagal (nginx/Apache)
- WAF mendeteksi ModSecurity yang sudah aktif di nginx, Apache, dan OpenLiteSpeed: Coraza tidak dipasang berdampingan (dua engine WAF tidak memeriksa request yang sama; badge di tab WAF) dan aturan ZySentinel dimuat lewat ModSecurity itu. Bila panel sudah memuat OWASP CRS atau Comodo, CRS tidak dimuat dua kali (mode pendamping) dan mode menyesuaikan sendiri bila CRS panel dipasang atau dicabut
- WAF di CyberPanel (OpenLiteSpeed) dipasang otomatis per situs bila ModSecurity panel aktif, dengan uji konfigurasi dan pengembalian otomatis bila gagal
- Edisi Free kini bisa dipasang di server tanpa control panel (Standalone, dengan UI web HTTPS dan login PAM) serta di cPanel/WHM, DirectAdmin, dan CyberPanel, selain aaPanel

## 🔧 Perbaikan & Peningkatan
- Panel multi-user (DirectAdmin, cPanel, CyberPanel): Process Guard kini menilai PHP setiap situs yang berjalan sebagai akun situsnya sendiri, hanya untuk proses web; sesi SSH, cron, dan FTP pelanggan hosting tidak terdampak
- Nama worker PHP-FPM berversi (php-fpm8.2, php-fpm82) dan OpenLiteSpeed dikenali sebagai worker web
- Semua layanan systemd plugin kini berjalan dengan sandbox (tanpa memuat modul kernel, tanpa namespace baru, syscall berbahaya ditolak): skor `systemd-analyze security` turun dari 8,4-9,6 (UNSAFE) menjadi 4,3-5,4
- Pemantau integritas sistem tidak lagi melaporkan unit systemd plugin "berubah" setiap kali plugin di-update
- Aturan whitelist firewall tidak lagi terpasang ganda untuk alamat yang sama (daftar putih tetap dan VPN terdeteksi otomatis)
- Pembaruan real IP per situs di balik CDN tidak lagi terhenti di tengah jalan saat pemasangan ulang firewall berkala selesai (sisa berkas sementara `*.tmp` dibersihkan)
- Process Guard tidak lagi membanjiri log untuk proses resmi yang diizinkan (mis. cron `git pull`): dicatat sekali per pola per jam dengan jumlah kejadian serupa
- Uji terisolasi Coraza kini mengatur izin berkas uji setelah semua berkas dibuat, sehingga tidak bergantung pada umask root
- Uji ruleset sebelum reload web server kini gagal dalam hitungan detik bila worker uji mati (dulu menunggu sekitar 70 detik)
- Pemasangan ModSecurity dari plugin di DirectAdmin dan cPanel kini ditolak dengan petunjuk lewat CustomBuild/EasyApache: Apache di panel itu dikelola panel, paket Apache distro akan bentrok dengannya
- Pembangunan konektor Coraza memakai rilis Go resmi bila Go SDK Manager aaPanel belum memuat versi Go yang dibutuhkan
- Audit Hardening Situs di cPanel: "Matikan TLS 1.0/1.1" mengubah pengaturan TLS global EasyApache (dengan cadangan dan uji) sehingga tidak ditimpa panel
- DirectAdmin dan cPanel: pemantau log membaca salinan access log milik root per situs secara langsung, tidak menunggu buffer log panel
- Audit Hardening Situs di OpenLiteSpeed (CyberPanel): "Matikan TLS 1.0/1.1" kini tersedia, dengan uji konfigurasi dan pengembalian otomatis
- Blokir WAF di OpenLiteSpeed dan nginx dengan ModSecurity yang sudah ada kini muncul di log WAF ZySentinel (disalin dari log audit panel)
- Audit Hardening Situs di DirectAdmin: "Matikan TLS 1.0/1.1" lewat pengaturan SSL CustomBuild (dengan cadangan dan uji), dan pengaturan TLS global DirectAdmin kini ikut diperiksa
- Pemasangan dan update plugin tidak lagi tertahan oleh unduhan data GeoIP di jaringan lambat: data diunduh di latar
- UI panel lebih ringan dan halus: scroll dasbor tanpa efek blur latar pada kartu, pindah tab lebih cepat, animasi peta dan grafik dasbor berhenti saat dasbor tidak terlihat

## 🐛 Fix Bug
- Tombol Escape kembali menutup jendela plugin setelah berpindah tab; sebelumnya hanya berfungsi sebelum tab pertama diganti
- Sinkron rentang IP CDN (Cloudflare, Fastly, dan lainnya) untuk real IP kembali memperbarui daftar; sebelumnya selalu gagal diam-diam dan memakai daftar bawaan
- Pesan galat Audit Hardening Situs dan pengaturan 2FA UI standalone kini tampil dalam bahasa yang dipilih, tanpa rincian teknis mentah (rincian dicatat di log)
- UI panel tidak lagi tersendat berkala saat dibiarkan terbuka, dan tidak makin lambat setiap kali plugin ditutup lalu dibuka lagi di tab browser yang sama
- Halaman block WAF (403) kini mengikuti bahasa yang dipilih di plugin (English atau Indonesia) dan langsung berubah saat bahasa diganti; dulu selalu Bahasa Indonesia
- Vhost contoh bawaan panel (example.com) tidak lagi tampil sebagai situs
- ModSecurity v3 (OpenLiteSpeed/nginx) tidak lagi berhenti mencatat audit untuk situs yang dilindungi ZySentinel
- Process Guard menghentikan juga proses turunan dari shell yang dibunuh, sehingga perintah yang sempat dijalankan shell webshell tidak lolos
- Pemantau log kini membaca log situs cPanel (domlogs bernama domain tanpa akhiran .log) dan tidak lagi menghitung log yang sama dua kali bila folder log dicapai lewat symlink
- Vhost internal panel (*.localhost) tidak lagi tampil sebagai situs
- WAF di DirectAdmin dan cPanel tidak lagi hilang diam-diam saat panel menulis ulang konfigurasi vhost (ganti versi PHP, SSL, tambah domain): include dipasang lewat mekanisme konfigurasi kustom resmi panel, dan include yang hilang dipasang kembali otomatis
- Situs DirectAdmin tidak lagi terdaftar sebagai www.<domain> sehingga WAF per situs bisa diaktifkan dengan nama domainnya
- Process Guard tidak lagi mencatat penyamaran palsu untuk proses web berumur pendek yang sudah keluar saat dinilai
- Process Guard tidak lagi memakai UID 1002 sebagai akun web cadangan di luar aaPanel (di panel lain UID itu bisa milik pelanggan hosting)
- Pemantau log kini membaca access log situs CyberPanel (baris berkutip ganda di folder /home); dulu tidak ada serangan ke situs CyberPanel yang terhitung. Lebih dari 16 folder log/konfigurasi tidak lagi terpotong diam-diam
- UI standalone di DirectAdmin/cPanel/CyberPanel kini melihat situs dan berkas di /home (daftar situs pemindai dan restore karantina)
- Process Guard kini menilai proses layanan host yang memakai sandbox systemd (mis. php-fpm/httpd distro dengan PrivateTmp); sebelumnya dilewati seperti proses container
- Pemindaian antivirus tidak lagi melaporkan "0 terinfeksi" bila klien clamdscan tidak terpasang (Debian/Ubuntu memisahkan paketnya): kini memakai clamscan, dan kode keluar pemindai yang gagal dicatat
- Pemeriksaan integritas sistem tidak lagi gagal (layanan "failed") pada pemasangan baru sebelum baseline direkam; pemeriksaan pertama merekam baseline
- Update plugin kini me-restart Process Guard yang sedang berjalan sehingga perbaikannya langsung berlaku; sebelumnya kode lama tetap berjalan sampai server reboot
- Status WAF per situs tidak lagi menampilkan "on" untuk situs yang dihentikan di panel (snippet WAF tidak dimuat web server); kini tampil "on, tidak dimuat" dengan penjelasan
- Uji terisolasi Coraza tidak lagi gagal di server ber-umask ketat (mis. 077): worker nginx uji tidak bisa membaca `rules.conf` ("permission denied"), semua request uji menjawab 000, dan Pasang ke nginx dibatalkan
- On/Off WAF per situs dan rule OWASP tidak lagi berhenti dengan "timeout setelah 60s" saat "Memuat ulang web server" bila uji ruleset gagal
- nginx uji yang tertinggal dari uji ruleset yang terputus (timeout panel) kini dihentikan otomatis pada uji berikutnya; dulu tetap berjalan sampai server di-restart
- Aturan firewall ZySentinel tidak lagi hilang setelah reboot atau `csf -r` di server ber-CSF (mis. DirectAdmin): dulu CSF menghapus chain SENTINEL dan server tanpa firewall ZySentinel sampai pemasangan ulang berkala 5 menit kemudian
- Self-heal kembali bisa memulihkan integrasi panel (menu plugin CyberPanel, port UI di CSF/ufw/firewalld); sandbox sebelumnya membuat berkas sistem hanya-baca sehingga pemulihan diam-diam tidak terjadi
- Pembangunan ulang konektor Coraza setelah upgrade nginx tidak lagi berhenti dengan galat "unbound variable" pada `waf.conf` yang tidak memuat kunci tertentu
